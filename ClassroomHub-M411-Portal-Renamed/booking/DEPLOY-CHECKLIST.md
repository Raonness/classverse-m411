# Deployment checklist — ต้องทดสอบก่อนเปิดจอง LIVE

- [ ] สร้างโปรเจกต์ Supabase ใหม่และรัน schema.sql ผ่านโดยไม่มี error
- [ ] เติมเฉพาะ URL และ publishable/anon key ใน `config.js` (ไม่ใส่ secret)
- [ ] ทดสอบ PUBLIC TEST ด้วย 2 บัญชีบน 2 เครื่อง; กดโต๊ะเดียวกันพร้อมกันและมีผู้ชนะเพียงหนึ่งราย
- [ ] รอให้การล็อกหมดอายุ 2 นาที ตรวจว่าโต๊ะกลับเป็นว่าง
- [ ] ตัดเน็ตฝั่งผู้จอง ตรวจว่าไม่สามารถยืนยันจากข้อมูลเก่าได้
- [ ] ตั้งเวลาเปิดจองอีก 10–30 วินาที ผ่านผู้ดูแลและกดตรวจสอบ → ยืนยัน
- [ ] ทดสอบ refresh / สลับแท็บ / เปลี่ยนนาฬิกาอุปกรณ์ ระบบต้องไม่เปิดจองก่อนเวลาฐานข้อมูล
- [ ] ยืนยันว่าข้อมูล PUBLIC TEST ไม่หลุดไป LIVE และล้าง PUBLIC TEST ไม่ลบ LIVE
- [ ] ตั้ง Supabase Auth Site URL และ Redirect URLs ให้ตรง GitHub Pages
- [ ] สร้างบัญชีผู้ดูแลอีเมลยืนยันและ whitelist `classroom_admins`
- [ ] ทดสอบว่าบัญชีปกติเข้าเมนู ADMIN SQL ไม่ได้ และไม่สามารถแก้ตารางผ่าน Data API โดยตรง
- [ ] เพิ่มรายชื่อ (เลขที่+อีเมล) ใน roster ผ่านผู้ดูแลหรือ SQL อย่างปลอดภัย
- [ ] ทดสอบรอบ LIVE: รับได้เพียงหนึ่งโต๊ะต่อเลขที่ แม้มีหลายผู้กดจองแทน
- [ ] ทดลองโหลดพร้อมกันประมาณ 40 คนและตรวจเวลาตอบสนองฐานข้อมูล
- [ ] เปิด CAPTCHA / rate limits เท่าที่จำเป็น และกำหนดนโยบายหากนักเรียนจองแทนโดยไม่ได้รับอนุญาต
- [ ] สำรองฐานข้อมูลก่อน LIVE, วางแผนผู้รับผิดชอบกู้คืน/แก้ไข/ลบข้อมูล
- [ ] เก็บข้อมูลนักเรียนเฉพาะที่จำเป็น และตั้งช่วงเวลาลบข้อมูลเมื่อจบกิจกรรม

**ยังไม่ถือว่าผ่านการเปิดใช้งานจริง** จนกว่าคุณจะทดสอบกับ Supabase จริงตามรายการนี้
